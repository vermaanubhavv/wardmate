WardMate · Sub-Processor Register

Where a patient's data actually goes

Every outside service that receives any data from WardMate on a hospital's behalf, what each one is sent, and why. Prepared for a unit's compliance review before onboarding — sourced directly from the running application, not from a marketing description of it.

Prepared: 16 Sep 2026 · updated 6 Oct 2026 Applies to: wardmate.in (production) Governing law: India · DPDP Act, 2023

Processors that see clinical data

These services are sent patient-identifying or clinical content — a transcript, a photograph, a diagnosis — because doing so is how the feature works. WardMate is the Data Fiduciary's processor here; each of these is, in turn, WardMate's own sub-processor.

Sub-processor Sent Purpose Retained by them?
AnthropicClaude API image text admission-paper photos, voice transcripts, lab-report photos, register photos, case-history text Reads the unstructured input and returns structured fields — diagnosis, bed, dates — for the doctor to confirm. Per Anthropic's API terms; confirm current retention/training settings in the account's data-handling agreement before launch.
Deepgramspeech-to-text audio raw voice recordings, incl. live-dictation streams Transcribes spoken bedside notes and live case-history dictation to text. The only speech-to-text provider. Every request is sent with mip_opt_out=true, so audio is excluded from Deepgram's model training. Other retention per Deepgram's API terms — confirm current policy.
TypeSafeJev API · hosted in the US text live-dictation fragments, each dictated value with its quote, plan wording, history-check quotes, lab-report lines and register rows as read off a photo. Never the photo or audio itself. Second look at what the Claude API produced: whether a quote actually says its value (a no turns the value amber for the doctor), which case-sheet section a dictated sentence belongs to, and whether a plan is still a job. Returns only a probability or a choice — it never writes clinical text. Not used to train models (DPA, typesafe.ai/legal/data-processing; 72-hour breach notice). Zero data retention requested 6 Oct 2026, pending TypeSafe's confirmation — once on, only billing and usage telemetry is kept. Their DPA lists sensitive data as "N/A"; whether it covers health data has been asked.

Infrastructure

These carry or store the data but aren't asked to read or interpret it as part of their job — the system of record, the servers it runs on, and the two that never see clinical content at all.

Provider Role Sees clinical data?
Supabase Database, authentication, and file storage — the system of record for every patient, entry, and photo. Hosted in Mumbai, India. yes — this is where it lives
Vercel Hosts and runs the application itself; every request passes through it. yes — in transit, not stored
Resend Delivers the 6-digit sign-in code by email. no — an address only, no clinical content
Sentry Crash and performance monitoring, dormant unless explicitly enabled. no — deliberately scrubbed before it leaves the server

What never leaves the ward

Fields the app never collects

  • No phone number, no home address. A patient record holds a name and a bed — a deliberate product decision, not an oversight.
  • No government ID of any kind.

Discarded after use, not stored

  • The audio and photo used to quick-fill the "Add patient" form are sent to Anthropic/the speech provider, used once, and never written to disk or database.
  • Session Replay (screen recording) is off in Sentry — it would otherwise capture a ward screen full of patient data.
This register is compiled from the running application's actual code and configuration — it is engineering fact, not a legal opinion. It doesn't establish a lawful basis for processing on its own; that still depends on the agreement between the hospital and WardMate, and on each vendor's own current data-processing terms, which WardMate does not control and should be checked directly before this document is relied on.
